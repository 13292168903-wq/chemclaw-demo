**日期**：2026-10-17　**范围**：`skills/chemclaw-analyze`、`skills/chemclaw-grade` 及其依赖的数据层

## 0. 层次定义

| 记号 | 含义 | 验证方式 |
|---|---|---|
| **组件** | 单函数/单模块级缺陷，输入输出可直接断言 | `node --test` 直接调用 `parsers.js` / `knowledge.js` 等 |
| **端到端（CLI）** | 真进程：`node skills/*/scripts/*.mjs` → stdout JSON | 子进程执行，解析 JSON 断言 |

### 2.3 只改文档（无法自动验证）

`skills/chemclaw-analyze/SKILL.md`：
- 「引用前的四道闸」：`ok:false` → `aborted` → `normalTermination:false` → `frequencyCount:0`
- **模板文本不是结论**：`explanations` / `learningGoals` / `quiz` 可能与 `metrics` 冲突，必须复核
- `null` 不是 0；`converged:false` 只能读作"没找到判据"；`unitsSource: as-written` 时须注明"单位未校验"
- 数值自检：`gap` > 30 eV 视为解析可疑

`skills/chemclaw-grade/SKILL.md`：
- 按 `consistency.status` 转述，不自行定容差；未核对时不得评价数值正确性
- `strengths` 只证明格式，不证明数值正确
- 检测到注入指令须显式上报

## 3. 详细日志

### T0 建用例（22:15）

写 12 份夹具 + `test/skill-cases.test.js`，先跑一遍看现状：

```
ok 1  … ok 10        （10 通过）
not ok 6  expected: 'XYZ'  actual: 'ORCA'   （纯坐标被标成 ORCA）
# tests 11  # pass 10  # fail 1
```

第一处真实缺陷即刻暴露：`parseAny()` 的兜底是 `parseORCA()`。

### T1 首轮独立评估（22:22）

把 12 份夹具、两份 SKILL.md、两个脚本交给评审子代理，要求"实际跑脚本、对照 stdout、找出会输出错误化学结论的地方"。它给出 6 条 P0：

1. 双虚频文件仍输出"符合一阶鞍点特征"（模板与判据冲突）
2. `converged:false` 被当成"未收敛"，连正常终止的样例都会被评为"结果不可信"
3. ORCA 的 Hartree 值被标成 eV（水 0.5357 → "0.54 eV 小 gap"）
4. ORCA 正常终止被报成失败
5. `frequencyCount:0` 被读作"无虚频 → 极小点"
6. `--metrics` 对输出零影响，交叉核对无法执行

另有 6 条 P1（契约示例非真实快照、无容差规则、错报告得分反而更高、`cm⁻¹` 不识别、命令路径跑不通、无中止判据）。

### T2 第一轮修复（22:28）

改 `parsers.js` / `knowledge.js` / `teaching-designer.js` / `analyze.mjs` / `grade.mjs`，重写两份 SKILL.md。验证：

```

            normalTermination true, frequencyCount 3
双虚频    : "检出 2 个虚频（首个 -512.3341 cm⁻¹）：这不是一阶鞍点…"
可复现    : 同一输入两次 JSON 深度相等
测试      : 74/74
提交       : 5517b9c
```

### T3 复检（22:35）

同一评审员只做复检。结论：6 条 P0 全部闭合，但**又发现 2 条新的 P0**：

- 多行 `Alpha occ` 只取第一行 → HOMO 取到上一行末尾，占据轨道多的日志偏差可达几十 eV（它的 9 值夹具报到 200+ eV）
- `units` 对"原样透传"的字段过度承诺：`HOMO = -0.24`、`78 kJ/mol` 被统一宣称 eV / kcal/mol

外加 1 条 P1：`consistency` 正则把 `B3LYP` 的 3 当成报告值。

### T4 第二轮修复（22:38）

- `parsers.js`：`matchAll` 取最后一个 occ 块最后一个值；能垒读单位串并换算；`orbitalUnit` / `barrierUnit` / `dipoleUnit` 标记来源
- `analyze.mjs`：新增 `unitsSource`（`Hartree→eV` / `kJ/mol→kcal/mol` / `au→Debye` / `as-written`）
- `grade.mjs`：正则要求"带单位 + 前面不粘字母/斜杠"，kJ 值先换算再比
- SKILL：`as-written` 的处理规则、"取数可疑时回读原文"、`mismatches` 示例改为真实对象
